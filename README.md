# NEMESIS USB Package Manager (prototype v0.1.0)

An independent Android 4.4/API 19-compatible front end for the [NEMESIS](https://github.com/xwtk/hmg_nemesis) package commands. It lets you retain multiple release folders on **one USB drive** and choose Install, Update, Launch, Uninstall, or Run from the head unit. It never rewrites the root `NEMESIS.data` and does not replace the upstream NEMESIS Manager.

**Status: experimental source prototype.** The APK and installable NEMESIS ZIP are created by the included GitHub Actions workflow or a machine with the Android SDK. A source ZIP alone cannot be installed into NEMESIS. This project has not been built or tested on a real Gen5W head unit in this environment. No automatic installation of third-party packages.

For full Windows instructions, see **[docs/SETUP-WINDOWS.md](docs/SETUP-WINDOWS.md)**. The build output includes those instructions directly on the USB. Detailed archive variants: **[docs/RELEASE-LAYOUTS.md](docs/RELEASE-LAYOUTS.md)**.

## Desired USB structure

```text
USB/
  NEMESIS.data          # permanent: type=execute, path=NEMESIS.sh
  NEMESIS.sh            # first insertion installs this manager; later opens it
  manager/
    usb.package.manager.zip
  packages/
    Mirror-Diagnostics/
      NEMESIS.data      # release's USB install descriptor
      packages/
        mirror.diag.zip
      data/              # persistent data / install logs
    Leafia-Plus/
      NEMESIS.data
      packages/
        <actual-release-package>.zip
      data/
    RearDashcam/
      NEMESIS.data
      packages/
        <actual-release-package>.zip
      data/
    Standalone-Package/
      NEMESIS.data      # generated by import tool, type=install
      payload.zip       # actual NEMESIS package ZIP, not extracted
      data/
```

Only the root `NEMESIS.data` is consumed by NEMESIS's normal USB handler. The installed **USB Package Manager APK** interprets the nested descriptors under `packages/` itself. You can also place a raw package ZIP directly under `packages/`, or a source package directory with an internal package manifest. Prefer one folder per release for separate data.

## First use (after NEMESIS itself is already installed)

1. Build via the supplied GitHub Actions workflow, or locally using the Android SDK and `gradle :app:assembleDebug`.
2. Download the CI artifact `usb-package-manager-ready.zip` and **extract** it to the USB root. It supplies root `NEMESIS.data`, `NEMESIS.sh`, `manager/`, and `packages/`.
3. Put other release ZIPs in your PC folder and run `python3 tools/import_release.py ReleaseName-usb.zip --usb E:\\ --name ReleaseName` (Windows) or manually extract each USB-ready ZIP **inside** `USB/packages/ReleaseName/`, never the USB root.
4. Plug USB into the car after NEMESIS is installed and Android is running. Confirm the one-time `execute` prompt. The launcher installs the manager if needed and starts its activity.
5. Tap an entry, then choose Install/Update, Launch, Uninstall, or Run. Every privilege-changing action requires on-screen confirmation.
6. Future insertions use the **same root descriptor and launcher**. NEMESIS asks before executing it; you never edit `NEMESIS.data` to switch package selection.
7. You can also open NEMESIS Manager > Packages > USB Package Manager > Launch without unplugging the USB.

This does **not** install NEMESIS itself. Use NEMESIS's official first-time setup instructions before this package.

## How each release is recognized

| Inside `packages/Name/` | Action |
| --- | --- |
| `NEMESIS.data` with `[nemesis] type=install` and `path=...` | Install the referenced package ZIP; supports Update |
| `NEMESIS.data` with `type=execute` and `path=...` | Run the referenced script with root privileges |
| `NEMESIS.data` with `id=...` but no `type` | Zip the source directory excluding `data/`, then install |
| `payload.zip` containing a true NEMESIS package manifest | Install from its ZIP |
| Broken path, missing manifest, unsupported descriptor | Mark invalid; do not execute |

The Android app scans USB paths documented in the upstream project (`/storage/usb0` etc.). Release files and `data/` remain on USB after uninstall. NEMESIS's **installed** package files and registry are managed by NEMESIS on the head unit.

## Per-package data

`packages/Name/data/` is reserved for user exports and `package-manager-history.log`. The manager never clears it. **Existing packages do not automatically change their own export locations.** RearDashcam defaults to `/storage/usb0/Dashcam` and documents a `DASHCAM_ARGS="--out=/storage/usb0/packages/RearDashcam/data"` setting in `/data/nemesis/apps/dashcam/dashcam.conf` (updates may reset it). Configure and test that separately before relying on recordings. If you do not reconfigure RearDashcam, leave its default `/Dashcam` folder alone.

## Safety and limitations

- Only use trusted packages: NEMESIS installation hooks and USB scripts execute as **root**. A bad package can corrupt the head unit.
- This manager calls upstream `nemesis pkg-info`, `install [--update]`, `uninstall`, `pkg-launch`, `pkg-list`, `root -c`; no custom privilege escalation or firmware patching.
- No batch installation. Firmware-specific packages may conflict or reboot during installation. A single explicit action at a time prevents unintended chains.
- It cannot guarantee that two third-party packages are compatible. **Leafia Plus** must not be installed alongside original conflicting wireless/projection patches per upstream compatibility notes.
- APK launching and removable USB mount permissions are **not yet tested on your exact 2023 Ioniq 5 firmware**. The provided CI build should be treated as experimental.
- Android's debug signature is a development signature, not a trusted production signing identity.
- Package installation errors remain visible in the confirmation dialog and are written in `packages/<Name>/data/package-manager-history.log` when available.
- `type=execute` is acknowledged when the USB mounts, and NEMESIS may auto-confirm when Android is down. The launcher checks `sys.boot_completed=1` before performing anything.

## Build

Requirements: Java 17+, Android SDK platform 35, Android Gradle Plugin 8.7.3, Gradle 8.10.2, Python 3.8+.

```bash
gradle :app:assembleDebug
python3 tools/build_release.py app/build/outputs/apk/debug/app-debug.apk
```

Files in `dist/`:

- `usb.package.manager.zip` is the NEMESIS internal installer ZIP (APK inside).
- `usb-package-manager-ready.zip` is the **USB-ready archive**; extract it onto an already-NEMESIS-equipped car's USB drive.

GitHub Actions includes an equivalent workflow and uploads both artifacts. Build locally or upload this source to a GitHub repository and run the `Build USB Package Manager` workflow.

### Windows bulk USB preparation

After downloading the built CI `usb-package-manager-ready.zip`, you can prepare everything in one command from a PowerShell terminal with Python installed:

```powershell
python tools/prepare_usb.py --usb E:\ --bundle .\usb-package-manager-ready.zip `
    --add .\downloads\leafia-release-usb.zip `
    --add .\downloads\dashcam-release-usb.zip `
    --add .\downloads\mirror-diag-usb-install.zip
```

This copies the permanent launcher to the USB root, imports each release into its own `packages/` folder, and creates `data/` for each one. Subsequent package-only imports use `tools/import_release.py` and require no edit to the USB root. Use `--overwrite` only when you intend to replace existing installation files. The importer always preserves an existing release's `data/` directory.
